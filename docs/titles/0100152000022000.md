# Mario Kart 8 Deluxe (0100152000022000)

**State:** v3.0.5 (update v1376256 + Booster Course Pass DLC) boots and races headless on the normal 64-bit path at 40-47 fps (title, menus, cup select, races). The base 1.0 build is AArch32 and runs through the lifted `a32jit.dylib` (written by `napple build`) at 52-60 fps in headless menus and the attract race; the runtime has no interpreter (2026-10-26, [a32-full](../archive/changes/2026-10-26-a32-full-2026-10-26-macos1.md)).

## What it needs
- `--update-romfs in-place` data (268 MB instead of ~19 GB), see [README](README.md#building-test-data-without-disk-pain-all-titles).
- Mii default CharInfo as UUID v4 (otherwise the AArch32 build faults at start), device and account saves mounted separately, display version from the NACP, `time:u` cmd 300, the A32 main-stack reservation.

## What is open
- The ~45 fps ceiling is gfx: guest blocked ~21 ms per present in SyncWait, per-submit commit to complete ~21 ms, present GPU <= 8 ms, replay CPU 0.7 ms (LAS runs 58 fps with the same code). Headless pacing as a timer reached 60 fps in one run (merge-sensitive).
- Resolved 2026-10-26 ([gfx-correctness](../archive/changes/2026-10-26-gfx-correctness-2026-10-26-macos1.md)): stale command handles (lists now live as long as their command memory), the compressed render-target shadow is copied back, a vertex stream outside every pool binds zeros (and streams no attribute reads are ignored), Metal API validation is clean through title, menus and a race. Still open: conditional rendering always enabled; `TextureInitialize: storage out of range` was not seen again in the 2026-10-26 routes (re-check with the golden harness).
- iOS Simulator: the G-buffer pass needs 48 bytes of colour attachment, the Simulator allows 32 (base, AArch32); 3.0.5 now gets past `time:u` cmd 300 and aborts at ~2.3 s on the same 48-byte limit (2026-10-26). `romfs.map` holds host paths: it works only in the Simulator, a device bundle needs the real RomFS.
- Binary archive load time (2026-10-26): a 59 MB `cache/pipelines-v8.metalar` left in the default save root by earlier runs took 65.5 s to load in `mtl_shader_init`; now a file over 16 MB loads in the background (draws compile meanwhile) and the file is capped at `NAPPLE_GFX_ARCHIVE_MAX_MB` (default 64). The Grand Prix menu's mode-preview panel is a black rectangle (a video preview; media, not gfx). The preview panels have played since the NVDEC / VIC path was completed (see "Runtime services").
- A32: 4,818,607 of 4,867,102 instructions are lifted inline (VFP and NEON included), 48,495 (mostly undecodable pool/table words) run as build-time decoded out-of-line operations, zero interpreter fallbacks and zero "no lifted code" stops in 150 s scripted runs and 112 headless runs. One run in 40 aborted inside `gfx_cmdrec_finalize_handle` (heap corruption in the command recorder after "command recorded outside BeginRecording/EndRecording"); no wild pc.
- Both the ios-sim and mk8d-64 branches add `time:u` cmd 300 (conflict in `services/time.c` at integration).

## Build and test
```bash
napple build <MK8D folder> -k "<Testing Material>/prod.keys" --firmware "<Testing Material>/Firmware.zip" --updates latest --dlc all --data-only --update-romfs in-place -o <out>
napple-runtime <out>/0100152000022000/fe941ed5ba14be5d --headless --seconds 120
```
`NAPPLE_INPUT_SCRIPT="15:A,19:A,...,140:A"` reaches the races (title "Ver. 3.0.5"); expected exit 0, 5362 frames in 120 s. A32: `napple build` writes `modules/a32jit.dylib`; run the `b5c39b5b7c62a88e` dir with `NAPPLE_A32_JITSTATS=1` (prints out-of-line operations and the unlifted-pc counter, which must stay 0). The interpreter only exists in the `make -C runtime A32_INTERP=1` debug runtime.
Materialising the patched RomFS of the update takes about 19 GB; the in-place data about 268 MB.

Boots 45 s: exit 0, 2442 frames, audio and scripted input OK, 6 save files written and mounted again.

## Bring-up notes
This title is the worked example of a bring-up ([bring up a new title](../guides/add-game-support.md)): every blocker found on the way has a row in [symptoms](../symptoms.md): Mii default CharInfo as UUID v4, `time:u` cmd 300, device and account saves, the A32 main-stack reservation.
- The base 1.0 build is AArch32: an svc without an `svc_sigs[]` row fails for it even when the 64-bit path works. `napple rewrite a32 --coverage` numbers per run are in the [a32-full change note](../archive/changes/2026-10-26-a32-full-2026-10-26-macos1.md).
- VFP/NEON run as out-of-line operations in part; in races the title executes about 10 million of them per second (the main cost of the A32 path).

## Runtime services
- Media: its movie library uses the three-argument `movie::Decoder` constructor; with `NAPPLE_MOVIE_MODECTOR` off (default) the mode-preview videos go through its own library to nvhost-nvdec + VIC and play; with it on the game waits for video the host decoder cannot start.
- The Grand Prix mode and cc-select preview panels play through nvhost-nvdec (H.264 on VideoToolbox) + VIC (NV12 pitch linear output); 300 decodes and 0 errors in a 110 s menu run (frames dumped with `NAPPLE_VIC_DUMP`).
- nvdrv: opens nvhost-ctrl, nvmap, nvhost-nvdec and nvhost-vic.
- `test_svc_caps_e2e` verifies the caps album round trip (caps:su save -> caps:u list -> LoadAlbumFile -> caps:dc / ImageIO decode) on real frames of this title (no reference title opens caps itself).
- `audren:u`: renderer revision REV1, `performance_frame_count` 0.
- Network connection applet: the evidence for the nifm Cancel / GetAppletInfo / netConnect output behaviour is this title's update nnSdk and the firmware's netConnect applet. Verified on Online Play offline: one CreateLibraryApplet 0xf per attempt, no retry, back to the menu.
- Offline web: its manual opens through `NAPPLE_OPEN_MANUAL` (OfflineHtmlPage under `html-document/`).

## Graphics
- NVN SDK 0.12.16 (the 1.0 build is 32-bit). As an AArch32 title its guest stack is not the host stack, so object-size traces cannot recognise stack temporaries: it sets up about 219,000 textures in 90 s, and its smallest texture gaps (0x8, 0x10, 0x40, 1 to 4 times each) are dead temporaries, not sizes.
- Keeps calling command handles after finalizing the command buffer that recorded them (the command-list lifetime rule in [gfx.md](../architecture/gfx.md)).
- Geometry programs (v1376256 patched + Booster Course Pass DLC): 1 (code 0x300) in `Common/Gfx/gsys_resource.Nin_NX_NVN.release.sarc`; not created in boot runs. Course and driver `.szs` model archives also carry shader programs.
- Shader corpus (base + updates + DLC): 26,544 programs, all translate and compile with Metal.
- Binary archive: a saved archive that gained nothing made `serializeToURL:` write nothing, which used to disable the archive ("renaming the saved archive into place failed").
- Its NVDEC + VIC submits, recorded with `NAPPLE_MEDIA_TRACE`, are the "trace" source in [nvdrv-layouts](../reference/nvdrv-layouts.md): the trace-derived H.264 picture words agree with the public header exactly, and the register its trace showed as "unnamed 0x140" is H264_SET_MBHIST_BUF_OFFSET.
- Golden-frame route: title to a race. Route still to add: cup select.
- Headless boot with `MTL_DEBUG_LAYER=1`: 60 s, exit 0, 0 unimplemented NVN calls, no validation message.

## Online (Napple Online, NEX)
Mechanism and server: [Napple Online](../guides/napple-online.md). This title is the first one the NEX server was built against (update v1376256, NEX for_NX 4.3.1).
- Trace setup: `NAPPLE_NET=host NAPPLE_ONLINE_SERVER=http://127.0.0.1:8737 NAPPLE_TRACE_IPC=all NAPPLE_ONLINE_DEBUG=1`, menu input `15:A,19:DOWN,20.5:DOWN,22:A` (Online Play, 1 player), and a save past the first-boot Mii selection.
- Game server name: `nsd:u` ResolveEx(`g2b309e01-%.s.n.srv.nintendo.net`), WebSocket upgrade with `Host: g2b309e01-lp1.s.n.srv.nintendo.net`. Names the binary carries: `g%08x-%%.s.n.srv.nintendo.net`, `g%08x-%%.p.srv.nintendo.net`, Pia's `nncs1-%.n.n.srv.nintendo.net` / `nncs2-%...` (redirected for the NAT check), `api-%%.znc.srv.nintendo.net` (blocked). Every name is redirected to the Napple server; nothing reaches Nintendo's servers.
- After login it calls SecureConnection 1 Register, Utility 7 GetIntegerSettings(0) and (1), Ranking 4 UploadCommonData; then the online menu ("Worldwide / Regional / Friends / Tournaments") is shown.
- Worldwide: MatchmakeExtension 40 AutoMatchmakeWithParam_Postpone; the server finds or creates a gathering (game mode 1, 12 places). Without the Notification 3001 "participant joined" about itself the title waits 10 s, unregisters and shows SessionKeepFailed (2618-0562); fixed by verbose gatherings (flags 0x200 / 0x800).
- NAT check: five zero packets to nncs1:33334, then types 101 / 102 to nncs1:10025, 103 to nncs2:10025; passes (natm=1, natf=1). Then Pia's NatDetectionJob sends `NATTestId_Dummy` packets to nncs1:33335 from a fresh socket (dropped).
- `nifm` GetCurrentNetworkProfile failed at the time of the trace (not implemented then).
- Status (2026-11-03): two instances on one Mac, through a local napple-online and a napple-room, match into one gathering, connect over Pia, reach character, kart and course vote, and the race countdown starts (verified, ~215 s run). The race itself (laps, results) has not been driven. Earlier blockers, each found with `NAPPLE_DEBUG_LOG` breakpoints on the Pia connect job and `NAPPLE_NET_LOG=2` datagram dumps:

| Symptom | Cause | Fix |
|---|---|---|
| the joiner ends with 2618-0502 ~150 ms after NAT traversal, no connection request | Pia's connect step (`ConnectStationJob`, main+0x99de0c; its check main+0x9330e8 -> main+0x94bd88) refuses a station it has not heard of | napple-online tells a joiner about every participant already in a verbose gathering, before its own join |
| the host answers the connection request with a refusal (result 1) | Pia looks a requesting station up by its IPv4 address only (main+0x9ae624): two instances on one Mac look like one station | each instance gets its room virtual address as its public address ([two instances on one Mac](../guides/napple-online.md#two-instances-on-one-mac)) |
| the course vote never ends | MatchmakeExtension 49 (gathering id) not answered | answered with the session like MatchMaking 41 |

- Scripted pair input: the menu steps by seconds, then the vote with frame-timed presses held 12 frames (`f3250:A:f12,f3340:A:f12,...`; a 0.15 s press is lost on the vote screen under load). The countdown shows after about 6000 presented frames. The 2618-0201 timing flake seen earlier did not reproduce in about 25 pair runs.
- Not implemented for this title: DataStore (115), the tournament ("Competition") and SimpleSearchObject methods, real rankings.
- Friends: with a Napple Account token a friend shows as online / joinable and the Friends menu opens, but the in-game friend list stays empty (open).

## Rooms (LAN Play and local wireless)
Mechanism: [online rooms](../guides/online-rooms.md). Update 3.0.5, two headless instances on one Mac in one room:
- LAN Play works: one instance creates a session, the other lists it, joins, and both reach the character select. Pia traffic flows both ways between 10.13.0.2 and 10.13.0.3. LAN Play is reached with A on the title screen, then L+R+left stick together on the main menu, then "LAN Play". LAN races use some tens of KiB/s per player.
- Wireless Play (local wireless) partly works: the host creates its room and the other instance lists and joins it, then the joining instance crashes inside the game (`signal 11`, `pc=main+0x9a3c84`): a Pia job registered in the worker's job list at menu time is zeroed before the join and dispatched at the join. Open; LDN Scan now takes ~400 ms like the console's (the scan screen used to loop at full speed), which did not fix it.
- Every player needs their own `--save-root` (that makes each instance a different console). Profile names are all "Napple".
- The fix that made LAN Play work was in bsd: the console's bsd service reports Linux errno numbers and Napple reported FreeBSD's, so the network library took "nothing to read yet" for a fatal error (2618-0006).
