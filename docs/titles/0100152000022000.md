# Mario Kart 8 Deluxe (0100152000022000)

**State:** v3.0.5 (update v1376256 + Booster Course Pass DLC) boots and races headless on the normal 64-bit path at 40-47 fps (title, menus, cup select, races). The base 1.0 build is AArch32 and runs through the lifted `a32jit.dylib` (written by `napple build`) at 52-60 fps in headless menus and the attract race; the runtime has no interpreter (2026-10-26, [a32-full](../archive/changes/2026-10-26-claude-a32-full-2026-10-26-macos1.md)).

## What it needs
- `--update-romfs in-place` data (268 MB instead of ~19 GB), see [README](README.md#building-test-data-without-disk-pain-all-titles).
- Mii default CharInfo as UUID v4 (otherwise the AArch32 build faults at start), device and account saves mounted separately, display version from the NACP, `time:u` cmd 300, the A32 main-stack reservation.

## What is open
- The ~45 fps ceiling is gfx: guest blocked ~21 ms per present in SyncWait, per-submit commit to complete ~21 ms, present GPU <= 8 ms, replay CPU 0.7 ms (LAS runs 58 fps with the same code). Headless pacing as a timer reached 60 fps in one run (merge-sensitive).
- `CallCommands: stale or invalid command handle` (65 k+ per minute: about 4000 lists/s never finalized, over the recording budget); `TextureInitialize: storage out of range (pool .. size 1769472 / 7077888)`; `vertex stream .. not inside a memory pool`; conditional rendering always enabled; compressed render-target shadow (format 0x44) not copied back.
- iOS Simulator: the G-buffer pass needs 48 bytes of colour attachment, the Simulator allows 32 (base, AArch32); 3.0.5 now gets past `time:u` cmd 300 and aborts at ~2.3 s on the same 48-byte limit (2026-10-26). `romfs.map` holds host paths: it works only in the Simulator, a device bundle needs the real RomFS.
- Binary archive load time (2026-10-26): a 59 MB `cache/pipelines-v8.metalar` left in the default save root by earlier runs took 65.5 s to load in `mtl_shader_init` (Metal `MTLMetalScriptBuilderImpl::initFromData`), so a 45 s headless run showed 0 frames; after that run rewrote it (34-37 MB) the next load took 2.6 s. Archive size/load time is not bounded yet (gfx).
- A32: 4,818,607 of 4,867,102 instructions are lifted inline (VFP and NEON included), 48,495 (mostly undecodable pool/table words) run as build-time decoded out-of-line operations, zero interpreter fallbacks and zero "no lifted code" stops in 150 s scripted runs and 112 headless runs. One run in 40 aborted inside `gfx_cmdrec_finalize_handle` (heap corruption in the command recorder after "command recorded outside BeginRecording/EndRecording"; gfx owner); no wild pc.
- Both the ios-sim and mk8d-64 branches add `time:u` cmd 300 (conflict in `services/time.c` at integration).

## Build and test

```bash
napple build <MK8D folder> -k "/Users/neto/Documents/Napple/Testing Material/Keys 22.1.0/prod.keys" --firmware "/Users/neto/Documents/Napple/Testing Material/Firmware.22.1.0.zip" --updates latest --dlc all --data-only --update-romfs in-place -o <out>
napple-runtime <out>/0100152000022000/fe941ed5ba14be5d --headless --seconds 120
```
`NAPPLE_INPUT_SCRIPT="15:A,19:A,...,140:A"` reaches the races (title "Ver. 3.0.5"); expected exit 0, 5362 frames in 120 s. A32: `napple build` writes `modules/a32jit.dylib`; run the `b5c39b5b7c62a88e` dir with `NAPPLE_A32_JITSTATS=1` (prints out-of-line operations and the unlifted-pc counter, which must stay 0). The interpreter only exists in the `make -C runtime A32_INTERP=1` debug runtime.
