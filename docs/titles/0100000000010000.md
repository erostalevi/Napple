# Super Mario Odyssey (0100000000010000)

**State:** plays on macOS (intro, menus, Cascade Kingdom); start menu on the iOS Simulator (a touch A did not visibly advance).

## What it needs
- The same fonts/libvpx as LAS; the shader archives register thousands of programs at once (so shader speculation is off by default).
- Command-list recordings must stay callable while the game can still call them (it records ~112 k display lists and replays them for minutes): `NAPPLE_REC_BUDGET_MB` (default 1024) bounds memory instead of the old 30 s idle release.
- Render scale: its G-buffer passes mix attachments; `pass_unify_scale` lifts them (fixes the half-scale duplicate view).
- NVN API version 53 with minor >= 13 in `game.json` (checked in `sead::GameFrameworkNx::initializeGraphicsSystem`); without it the title skips graphics initialisation silently.

## What is open
- Exploded geometry after a long idle (parrot after ~2 min): command lists now live as long as their command memory (no idle or budget release, [gfx-correctness](../archive/changes/2026-10-26-gfx-correctness-2026-10-26-macos1.md), `t_cmdlife`); the 215 s repro at frames 8000/9000 was not re-checked with the fresh-boot route because on the 2026-10-26 base the guest stalls at about 7 500 frames (a priority-47 worker holds core 0 in a long CPU loop and the priority-44 main thread waits in `core_take`; kernel scheduler, not gfx). Re-check the shattered cap brim and white ribbons on the title menu, grass blade streaks, purple sky, dithered dark Mario silhouette (probably separate programs; bisect with `NAPPLE_DEBUG_SKIP_VS`). See [symptoms](../symptoms.md).
- A 400x228 mipmapped pass is not scale-unified on purpose.
- A phantom MFi pad showed the settings sheet once on the Simulator (not reproduced).

## Build and test
Data as in [README](README.md#building-test-data-without-disk-pain-all-titles). Headless 45 s: exit 0, 0 CRASH (1921-2232 frames; 3571 frames in 80 s with scripted input and no orphan pick).
Repro of the idle bug: `NAPPLE_INPUT_SCRIPT="30:A:0.3,45:A:0.3,60:A:0.3"` boots the first kingdom (frames ~7000-9000); run about 215 s and screenshot frames 8000 and 9000.
Re-run 2026-10-26 with budgeted recordings, in-place data and the default save root: **not fixed.** 12441 frames, exit 0, 0 CRASH, but the 1024 MB budget was hit at ~frame 5900 (185095 lists alive, LRU release) and from ~frame 7600 the game calls two released lists (handles 0x100001d31, 0x1000026db): 18 `CallCommands: stale or invalid command handle` warnings. Frames 8000 and 9000 show the scene broken (a large black triangle and a striped mesh over a washed-out sky). The LRU release frees lists the game still replays; a budget alone does not fix it. (Lists are now kept as long as their command memory; see "Graphics" below.)
Corpus guard: `t_smo` translates and compiles 128 of 128 shaders (needs game data).

## Numbers
- Live play: steady 60 fps, GPU 6-12 ms, 4 of 51 five-second windows stalled (worst 990 ms at the scene change, 656 pipelines built in one window). Peak RSS 2.0 GB.
- Live recordings peak at ~112 k (265 k at 215 s without any release, about +1.7 GB).

## Timing
Guest cadence 60 Hz: trace at all fps modes: vsync 60.00 Hz, game clock 1.000, presents ~57/s. Windowed 60 s soak vsync on: p99/median 1.009, drift -0.10 frame. The logic runs on a variable delta time (clock-driven) with 60 Hz vsync-paced presents, so a faster present rate shows repeated images; a timestep/delta patch would be needed for real extra game frames (not done).
(How each title ties its logic to vsync is inferred from its cadence and engine class, not verified by patching.)

Golden route: 15451 frames in the last end-to-end run, frames 8000/9000 reached (no golden approved for them yet); the threads.c stall after ~7,500 frames did not reproduce in the last two runs (known flaky).

## Runtime services
- `vi:u`: the title's SDK creates an `android::Surface` eagerly, which is why IHOSBinderDriver answers every IGraphicBufferProducer transaction (NVN never uses it).
- `bsd:u` `RegisterClient` answers 0 because a nonzero client id broke this title's boot.
- Save data: creates `File1.bin` / `Common.bin` and calls Commit.
- `audren:u`: renderer revision REV3, boots with `performance_frame_count` 0 (the performance buffer is not exercised).
- nvdrv: opens no nvdrv device; boots unchanged with movie audio (Vorbis) on.
- Offline web: its manual opens through `NAPPLE_OPEN_MANUAL` (OfflineHtmlPage under `html-document/`) and is shown in the web sheet.

## Graphics
- NVN SDK 3.5.1 (object sizes measured with `NAPPLE_GFX_OBJTRACE`; table in the [title notes](README.md#graphics-measurements)).
- Overriding `nv::SetGraphicsAllocator` crashes this title; the allocators run natively.
- It finalizes per-model scratch command buffers and replays their lists for minutes; releasing lists by idle time or a memory budget made models draw without their setup (exploded geometry). Hence the command-list lifetime rule in [gfx.md](../architecture/gfx.md).
- A register-indexed constant-buffer read past the bound size produced garbage skinning bones until reads were bounds-checked (`cbuf_ref` / `cbr`).
- Sets `NVN_TEXTURE_FLAGS_IMAGE` on every screen-sized render target (so that flag is not a render-scale veto).
- Geometry programs: 2 distinct (line strip, 64 and 2 output vertices) in `ShaderData/alThunderShader.szs`; 3 hashes are created at boot. The stage data that references thunder (inferred from the data, not seen drawn): the travel cutscenes (`DemoWorldMove*StageDesign` with `RequestThunderVtxNum`, `DistantDemoWorldMoveThunder`), New Donk City, the Ruined Kingdom, the Moon Bowser stages. None is reachable by a scripted 120 s run from the saves on hand (they reach Cap Kingdom / the airship intro), so no draw has bound one in a boot.
- GLSLC vertex handles: before the translator read `SR_INVOCATION_INFO` / `ISBERD` handles, every handle was 0x80000000 and the kernel read another record, so the lightning lines collapsed to a point. With the dumped programs (`t_stages_dumped`) the 3 boot-time programs go through the geometry stage with finite output, and the pass-through line program reproduces each input line exactly.
- Shader corpus (base + updates + DLC): 31,750 programs, all translate and compile with Metal (the `LEA.HI` constant-buffer form was found in its compute programs).
- Golden-frame route `title-and-kingdom`: title and first kingdom; frames 8000 and 9000 are the sleep scene that showed exploded geometry.
- Headless boot with `MTL_DEBUG_LAYER=1`: 60 s, exit 0, 0 unimplemented NVN calls, no validation message.

## Rewriter and module tables
- The Rust NTB1 writer produced byte-identical tables to `tools/prepare_tables.py` on this title (and on Link's Awakening); it boots identically with the Rust and the Python rewriter; its `subsdk0` needs `ldrsw_table_scan`.

## iOS Simulator
- Reaches the Start / Assist Mode menu (about 55-75 s after launch), audio without underruns. Footprint 743 MB steady, 861 MB peak at the menu.
- A on the menu: the Simulator GPU's 32-byte colour-attachment limit stops it (`This set of render targets requires 48 bytes of pixel storage`, in `build_pipe`), or the process sits at 0 % CPU after "Compiling shaders". Devices with A11 and later allow 64 bytes (unverified).
- A tap on the touch A button did not visibly advance the menu (Simulator touch delivery from the tools does not reach the app).
- Expect a 1 GB+ footprint once in the world on a device (estimate).
