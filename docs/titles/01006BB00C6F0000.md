# Link's Awakening (01006BB00C6F0000)

**State:** plays on macOS (the most mature title); reaches its title screen on the iOS Simulator.

## What it needs
- Fonts in `<save-root>/system/fonts` for text (without them the placeholder font is served and no text renders; see [symptoms](../symptoms.md)).
- libvpx for its movie path (video decode through the guest's own movie library would hit an unimplemented NVN call without it).
- A write of its lower guest address gap: it needs more than the 3.25 GiB iOS device heap cap (it aborts in the movie library); the Simulator uses 4 GiB.
- Lower-left NVN origin; 85 of its shaders read SR_Y_DIRECTION (value -1). The shader corpus guard `t_las` translates and compiles 679 of 679.

## What is open
- First-use pipeline/shader build stutter (170-1300 ms when entering a new area); the second visit is smooth. Fix direction: persisted keys and seeds (done), async build with fallback (needs a design decision).
- A sustained ~30 fps state reported once did not reproduce in 5 live runs.
- iOS device: the memory cap above (decision: trim the low gap or require the increased-memory entitlement). Not run on a device. A later Simulator run with the device window (`NAPPLE_HEAP_CAP_MB=3328 NAPPLE_ALIAS_GIB=1`) booted, played the intro movie and reached the new-game flow, so the movie-library abort did not reproduce.

## Build and test
Build the data as in [README](README.md#building-test-data-without-disk-pain-all-titles) (about 250 MB). Headless 45 s: exit 0, 0 CRASH (2290-2723 frames, 58 fps headless; one scripted run reported 2647 frames with in-place RomFS).
The title screen needs the L+R chord (`NAPPLE_INPUT_SCRIPT` with `L+R`); `NAPPLE_INPUT_SCRIPT` reaches the file select.
iOS Simulator: see "iOS Simulator" below and [ios](../architecture/ios.md).

## Numbers
- 60 fps live windowed in a 3-6 minute play (perf-las-live), GPU 6-12 ms; headless 58 fps.
- Memory: guest ~1.2 GB, IOAccelerator ~320 MB; peak RSS 1.96 GB (fixed graveyard) to 3.4 GB (before), 3.7 GB worst seen.
- Audio latency drifted 21 to 44 ms over 4 minutes, no underruns (not investigated).

## Timing
Guest cadence 60 Hz (swap interval 1): headless trace at fps modes game/60/120/30/uncapped (20 s each): guest vsync 60.00 Hz, game clock 1.000, presents 55-60/s (GPU/CPU bound, see above). Logic is vsync-stepped (the intro movie and the game advance one step per vsync/present), so the present rate cannot add real game frames: higher display rates repeat/interpolate images only. A timestep patch is needed for real extra frames. Windowed 60 s soak: vsync drift 0.13-0.16 frame; p99 present interval is 2.1-2.2x the median because the presenter itself delivers 52-56 fps (the known gfx throughput limit), not because of pacing.
(How each title ties its logic to vsync is inferred from its cadence and engine class, not verified by patching.)

## End-to-end run
From `tools/e2e/run.sh` ([testing guide](../guides/testing.md#end-to-end-toolse2erunsh)): built through Studio, launched through the launcher, 45 s headless.
- Mii: the title never opens `mii:u` in the 45 s route; the shared database is still served to any title that does (see MK8D). Mii Maker (firmware applet) built into the app and verified with scripted input.
- amiibo: `nfp` is never opened (no abort with the reader installed lazily: `NAPPLE_AMIIBO` run, exit 0). Known flaky: an intermittent early abort `SetTerminateResult 0x35f202` (fs 2-6905) 0.4-0.8 s after start (about 1 start in 5, not reproduced with tracing on); it is a title-side abort after fs probing, not an nfp problem.
- Overlay: all four tabs render (Audio/Video, FPS/Speed, Controls, Game/System with the amiibo source/key fields).
- Camera/IR: usage strings and entitlements are in the app; the title does not use the IR camera. Online: NullProvider (offline).

## Runtime services
- `apm`: sets a "docked" performance id while in handheld mode and stops if it is refused, which is why `apm` accepts every id in both modes.
- Save data: calls Commit 5 times at start-up (nothing pending) and after saving.
- NVN API version 55.15 (the gfx default when `game.json` has 0,0).
- Movie: the opening movie goes through `movie.c` in NVN texture mode (mode 2): VP9 1920x1080 on libvpx plus Vorbis 48 kHz 6-channel on stb_vorbis with out-of-band headers; 6600 frames, 0 errors in the verification run.
- `audren:u`: renderer revision REV7, `performance_frame_count` 0.
- nvdrv: opens no nvdrv device.
- Software keyboard: the new-file name entry (needs L+R; the keyboard opens at about 109 s on a fresh save) uses swkbd normal mode: initial text "Link", length 1..8, invalid-character flags 0x12c, header/sub/guide words all zero; `NAPPLE_SWKBD_ANSWER` is returned and read back by the game (its next call passes it as the initial text).
- Legal information: its IP-notices page opens in the web sheet from `<data-dir>/legal/`.
- ISelfController 120 SaveCurrentScreenshot verified with `NAPPLE_DEBUG_SAVE_SCREENSHOT`.
- Scheduling: the one busy-wait seen so far (an applet message event that was never de-asserted) was a service bug, not a missing time slice.

## Graphics
- NVN SDK 8.2.0; accepts NVN API version 55.15.
- No geometry, tessellation or transform feedback programs (v0 scan: 6,429 programs, 2,881 / 2,858 / 26 distinct vertex / fragment / compute).
- Shader corpus (base + updates + DLC): 5,767 programs, all translate and compile with Metal.
- Sets `NVN_TEXTURE_FLAGS_IMAGE` on every screen-sized render target.
- With Metal shader validation (`MTL_SHADER_VALIDATION=1`) the GPU watchdog fires on heavy passes: 2 `GPU Hang` errors in 110 s, no validation message.
- Golden-frame route: boot to the village. Routes still to add: beach, forest.
- Headless boot with `MTL_DEBUG_LAYER=1`: 60 s, exit 0, 0 unimplemented NVN calls, no validation message.

## Rewriter, tables and signatures
- `main` keeps live locals in the 128-byte red zone of leaf functions, which is why the rewriter spills at `[sp,#-144]`.
- The Rust NTB1 writer produced byte-identical tables to `tools/prepare_tables.py` on this title (and on Super Mario Odyssey); it boots identically with the Rust and the Python rewriter; its `subsdk0` needs `ldrsw_table_scan`.
- REA/Ghidra on a 64 KiB slice of `main` starting at a function start returned the function boundary in about 12 s (whole `napple sigs resolve` run).

## iOS Simulator
The first-device candidate: the only reference title that boots, renders correctly and plays on the Simulator.
- Base v0: intro movie (VP9 on the iOS libvpx) at about 61 fps, audio on RemoteIO, the title screen ("Press L+R") at about 95 s, 55-60 fps; the touch controller is drawn. Scripted A presses do not leave the title (it wants L+R).
- With scripted keys (`NAPPLE_INPUT_SCRIPT="100:L+R,112:A,119:A,126:A,133:DOWN,138:A,..."` and `NAPPLE_SWKBD_ANSWER=Link`) it goes from boot through the file select, difficulty and name entry to gameplay in Marin's house, 57-60 fps, everything rendered correctly.
- Footprint (`phys_footprint`, audio off): 550-620 MB steady at the title and menus, 640 MB peak in the intro movie, 780-790 MB in play; guest-mapped 3.28 GB of virtual size, almost all untouched. The GPU share is not counted on the Simulator.
- Unsigned device IPA (`--target ios --no-sign --ipa`): about 4.0 GB compressed, 169 files, 4 dylibs.
- On a device: press L+R (the touch L and R together) at the title, A through the menus, A on the name field (keyboard applet) then down to OK. Expect 60 fps at 720p (handheld default).
