# IPC provider hooks (round 11)

Branch `ipc-provider-hooks-2026-11-03-r11`. Converts 12 documented-default `IPC_STUB` rows that depend on the network, the account or the
cloud into real behaviour through the `OnlineProvider` seam. The NullProvider answers what an offline console does, so a build without a provider
is unchanged.

## Rows converted (12 `IPC_STUB` to `IPC_IMPL`)
| Service | Rows | Provider hook |
|---|---|---|
| friend:u IFriendService | 10110, 10111 GetFriendProfileImage(WithImageSize) | `friend_profile_image` |
| friend:u | 10200 SendFriendRequestForApplication | `friend_send_request` |
| friend:u | 11000, 11001 GetProfileImageUrl(V2) | `friend_image_url` |
| nifm IRequest | 22 GetAdditionalInfo, 26 GetNetworkAccessStatus | existing `net_info` (the host provider's interface) |
| acc:u0 | 102 AuthenticateApplicationAsync, 120 CreateGuestLoginRequest | existing `account_id_token` |
| IManagerForApplication | 150 CreateAuthorizationRequest | existing `account_id_token` |
| olsc:u | 18 GetSaveDataBackupInfoCache, 27 UploadSaveDataBackupAsync | `cloud_backup_info`, `cloud_backup_upload` |

`online_provider.h` gained, append-only: `friend_profile_image`, `friend_image_url`, `friend_send_request`, `cloud_backup_info`, `cloud_backup_upload`
and the struct `OnlineCloudBackup`. `ABI_VERSION` is unchanged (`ONLINE_FN` hides them from modules built with a smaller struct).

## Behaviour
- **Friends:** with `ONLINE_CAP_FRIENDS` and the hook, 10110/10111 return `{u32 size}` plus the picture in the output buffer (size 0 = no picture);
  10200 returns the provider's result; 11000/11001 rewrite the URL in the input buffer for the edge size. Without the hook or the capability the rows
  end with the friends "network service account unavailable" result, as before.
- **nifm:** 22 and 26 only change while the request was accepted and the provider reports a connection (NAPPLE_NET=host): 22 returns a 0x10-byte
  record `{u8 kind, u8 strength, u16 0, u32 ip, u32 gateway, u32 dns1}`, 26 returns 1. Otherwise 22 reports the request's failure and 26 a zero word, as before.
- **acc:** 102 ends with success when the provider issues an ID token for the local user (the Napple account path); otherwise nifm's no-network result
  (no connection) or registration-required (not linked). 120 and 150 hand out `IGuestLoginRequest` (GetSessionId, LoadIdTokenCache) and
  `IAuthorizationRequest` (GetSessionId, InvokeWithoutInteractionAsync, IsAuthorized, GetIdToken; GetAuthorizationCode stays an `IPC_STUB`, an OAuth code
  needs a Nintendo Account server) only when the provider has `account_id_token`; otherwise the generic error as before.
- **olsc:** for a connected, linked user 18 returns a local 0x20-byte record `{u64 size, u64 last backup, u64 title id, u8 exists, u8 pending}`
  from `cloud_backup_info` (an empty record when the cloud does not know the user); 27 starts `cloud_backup_upload` and hands out an
  `IAsyncTransferRequest` with its result. Without the hooks the rows end like 19/22/25/26 (no-network or registration-required).

## Tests
`runtime/tests/test_svc_provider_hooks.c` (friend + nifm), `test_svc_provider_hooks_acc.c`, `test_svc_provider_hooks_olsc.c`: C fakes of the provider; the
NullProvider and the hook-less provider answers are checked next to the converted ones. Two older tests (`test_svc_nifm_audit.c`, `test_svc_fsacc_r10_olsc.c`)
asserted that the rows are stubs and now assert `IPC_IMPL`.

## Not done
- The Napple online glue (`net_online*`) does not implement the three friend hooks: the social server has no image, URL or by-id request endpoint (a
  request there is by friend code), and friend ids are hashes of profile ids. `cloud_backup_*` are not wired to `napple-cloud` either: `cloud.c` exposes
  no status call that C can read per user. Both are one-function additions once the server / FFI side exists.
- All layouts marked `[unverified]` in the code (input offsets of 10110/10200/11000, the 18 and 22 records, the 26 value, IAuthorizationRequest ids) follow
  switchbrew / libnx where they exist and are otherwise this runtime's own.
