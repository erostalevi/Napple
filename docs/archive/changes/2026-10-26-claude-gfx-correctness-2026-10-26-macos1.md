## ACNH window pass: fixed, stopgap removed (verified)
- Root cause: the window helper at `main+0x3802394` (called from `main+0x37b8f44`) and other first-frame code create programs with `nvnProgramSetShaders` whose code address is a **bare offset into a shader-code pool** (0xe00, 0xa200, 0x900 ...: the base the game adds is 0), about 30 calls per run. We rejected them (`code < 4 GiB`), `ProgramSetShaders` returned 0, and the game checks the result (`tst w0,#0xff` after the call at `main+0x3807614`) and then never records the program bind, the uniform-buffer binds or the texture bind of that pass. The window draw therefore ran with whatever the previous draw left bound (the 500x110 label), which is why all earlier notes found "no op names composite slot 1634" and presented the orphan composite as a stopgap.
- Fix (`gfx/src/api_program.c`, `api_memory.c`, `mtl_replay.m`): the call succeeds; each stage gets a placeholder hash (high word `PLCH`) and the replay resolves it at the first draw, when the game has filled the pools: the **oldest shader-code pool that has an NVN shader header (magic `0x12345678`) at the offset of every stage of that call**, and whose header's stage field (SPH word at +0x30, low 5 bits: 1 vertex, 2 fragment) matches the stage (a single offset matches several pools by chance and gave other programs' code: a vertex shader that wrote no position, fragment shaders that wrote varyings). With that the game records the full window pass (BindProgram, 4 UBO binds, BindTexture stage 1 slot 1634 = the composite, quad draw) and the picture is the real scene: Nook Inc. counter with Timmy's dialogue at frames 1400 and 1800 (screenshots checked), 0 skipped draws, 0 Metal compile failures, no orphan warning. `mtl_frame_present_pick` and its tables are **removed** (`NAPPLE_NO_ORPHAN` is gone); `NAPPLE_PROGRAM_POOL_OFFSETS=0` restores the rejection for comparison. Test: `t_progoffset` (a shader-code pool, bare offsets, red triangle).
- What is still approximate: the pool is found by content, not by the true GPU base (never found: the game's cached pool address for these programs is 0 and no NVN call returns it). A program whose shaders do not all have headers at their offsets in one pool stays unresolved (its draws are skipped; none seen in the 110 s ACNH runs). The two stages of one call must come from one pool.
- Other findings of the investigation: `nvnProgramSetShaders` is also called with a NULL code address (offset 0, accepted the same way now); the 15 `flags 0x62` shader pools are never asked for their address (`NAPPLE_POOLLOG=1` logs the queries); a program object received a guest write at its stage-4 hash slot (value 3), ignored with a warning.
- Diagnostics added (env only): `NAPPLE_POOLLOG=1`, `NAPPLE_WINDRAWLOG=1` (window draws: pipeline, viewport, scissor), `NAPPLE_DEBUG_NOCULL=1`.

## ACNH characters (Timmy and Tommy) missing: fixed (verified)
The counter scene drew without the two Nooklings (and the kiosk at the right). Not the window pass: the depth pre-pass / EQUAL colour pass draws them (`d3e5ad285bd50714` / `e3ad4a1919bc281f`, 9660 indices, 6 draws each) with every input bound (bone palette in UBO slot 3 = `cb6`, 0x5d0 bytes; the old draw log printed only UBO slots 0-3 and hid that). The skinned vertex shader read `cbr(cb6, cbsz[6], r19 + 65520u)`: Maxwell `LDC`'s 16-bit immediate is **signed** (`c[6][R19 - 0x10]`, as nvdisasm prints it and yuzu decodes it); the translator took it unsigned (after Ryujinx's field name), so every bone row below the index register was read 64 KB past the buffer, `cbr()` returned 0 and the skinned positions collapsed to a point. Fix in `gfx/src/shader/maxwell_translate.c` (sign-extend; `- N` in the MSL; a negative offset with no register reads 0), `TRANSLATOR_VERSION` 9 (invalidates cached MSL), `t_xlate` case. Frames 1400 and 1900 now show both characters with their shirts and the flag; `make -C gfx test` green. The translator is f64-isa's path: one hunk, listed in the integrator file as a conflict hotspot. The same bug could have hit any skinned mesh in any title (LAS and SMO used positive offsets in the shaders checked; re-booted after the fix, see the integrator file).
