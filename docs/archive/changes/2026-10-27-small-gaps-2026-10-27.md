# small-gaps (2026-10-27): nine small catalog items

Branch `claude/small-gaps-2026-10-27`, Linux cloud session. Status words: *tested* = unit tests pass on Linux, *unbuilt* = never compiled on macOS, *proposed* = reasoned, not checked
against a file or a title. Nothing here was run on a Mac, a title or a real dump.

## What changed

| Item | Result | Status |
|---|---|---|
| Personalized tickets | `ticket.rs` `encrypted_title_key`: RSA-2048 OAEP (SHA-256, MGF1-SHA-256, empty label) with the user's `eticket_rsa_keypair` (hex of the 0x230-byte device key: D, N, E). `num-bigint` for the modular exponentiation, padding checks reject every failure with one error. `ingest`/`package` pick the title key through it. A personalized ticket without the key is skipped as before | tested against an OpenSSL vector and corrupted blocks |
| IVFC verification | new `ivfc.rs`: parses the header, checks the master hash and every hash level; `nca::romfs_data` does that on open (levels above the data are tiny), `romfs_data_verified` also streams the data level through the tree. Headers with no tree (the old synthetic images) pass through | tested on built trees (valid, level corruption, data corruption, bad headers) |
| NCA2 / NCA0 | `nca.rs` reads NCA2 (each FS header XTS-decrypted at sector 0 instead of the continued numbering) and NCA0 (same, plus a 0x100-byte RSA-OAEP key area decrypted with the user key `nca0_key_area_rsa` = D\|\|N). NCA1 stays unsupported | NCA2 tested on a synthetic image; **NCA0 proposed** (key name, OAEP parameters and layout are from memory) |
| NSZ / XCZ | `ncz.rs`: a first section that straddles the raw 0x4000 header boundary (recorded from 0xC00 by some writers) is trimmed instead of rejected, for both the stream and the block form. The existing round trip, hostile-input and XCZ-ingest tests still cover the parser | tested on synthetic NCZ; the real dump check is a Mac/user step |
| audren performance metrics | the performance frame is kept in a history of `performance_frame_count` frames and handed over oldest first (whole frames only, chained by next_offset); the single-frame behaviour is the count 0/1 case | tested; header layout and modelled costs are still unverified |
| audin source wiring | the first OpenAudioIn installs the source named by `NAPPLE_AUDIN_SOURCE`: `silence`, `tone:HZ[:AMP]`, `file:PATH` (WAV or raw s16le, looped, resampled), `mic`. `mic` is an AUHAL input unit into a 48 kHz mono ring (`audin_mic.c`). The microphone stays opt-in: without `NSMicrophoneUsageDescription` and the audio-input entitlement a bundled app would be killed on first access | sources and the ring resampler tested; **mic unbuilt** (syntax checked with stubs in `tools/linux-check`) |
| GameCube / Palma / NES styles | `NAPPLE_STYLE_*` bits for the Lark, Lucia, Lagon and Lager pads; `choose_style` picks GC/Palma/NES when the title announces them and the player's binding style asks for them (or the title supports nothing else); style to lifo mapping, attributes (GC wired) and the six-axis index; binding JSON `gc`/`palma`/`nes`. The GC trigger lifo is **not written** (its offset in the entry is unverified) | tested through the real writers and `napple_input_update` |
| irs leftovers | rows 302, 315, 316, 317, 319 are implemented (activation state, function level, the Ex transfer = the transfer processor, LED accepted); 310 (tera plugin) and 312 (pointing) stay stubs because their output layouts are not documented | tested |
| bcat storage | provider hook (`bcat_set_provider`), folder provider (`NAPPLE_BCAT_DIR`), directory Open/Read/GetCount/Close, file Open/Read/GetSize/GetDigest, EnumerateDeliveryCacheDirectory, MD5 digests; sync succeeds when a provider exists. No provider = unchanged offline answers. The user's folder is read only | tested with a folder fixture and MD5 vectors |

## Decisions

- Keys the user must supply, never committed: `eticket_rsa_keypair`, `nca0_key_area_rsa`. Both are looked up by name in prod.keys with any length (`KeySet::get_vec`).
- The microphone is off unless asked for (env). The camera rule of the user (ask only when a game needs it) is the model: an audin stream opening is the "game needs it" moment, but the usage description has to exist first.
- bcat reads a folder the user fills; the repository carries no delivery client. A private build plugs a downloader in through `BcatProvider`.
- The GC trigger lifo and a Palma-specific state layout were left out rather than guessed at.
