# claude/a32-full-2026-10-26-macos1 (2026-10-26): full AArch32 lifting, no interpreter in the shipped runtime

## What changed
- **No interpreter in the shipped runtime.** `a32_run`, the instruction cache and both decoders are compiled only with `make -C runtime A32_INTERP=1` (`NAPPLE_A32_INTERP`; the debug / oracle build) and into the host tests. The runtime runs lifted code (`a32jit.dylib`) and, for the operations the lifter does not inline, `a32_op_exec`: the executor's semantics routines called with an instruction **decoded at build time** (the lifter writes the `A32Insn` + raw word as read-only data next to the code, `_a32jit_fb` passes its address). Nothing is fetched from guest memory or decoded at run time. A pc without lifted code stops the thread (`no lifted code at this pc`); there is nothing to fall back to. `tools/check_a32_no_interp.sh` proves it for a built runtime (no `a32_run` / decoder symbols, no `MAP_JIT` / `PROT_EXEC` in the A32 sources, dylib + manifest in the data dir).
- **`napple build` always lifts AArch32 titles** (`NAPPLE_A32_RECOMPILE=0` skips; before it was opt-in). A data directory without `a32jit.dylib` cannot run.
- **`napple rewrite a32 --coverage <modules dir>`**: lifts without assembling and prints, per module and operation, how many instructions are not inlined, with the first address and encoding of each group (full list in `<work>/j.cov`). `A32LIFT_WHY=<addr>` prints the discovery flags of an address.
- **Inline lifting** (verified lifted vs interpreter with `difftest`, see below), new in this branch: lda/stl (acquire / release with `dmb`); flag-setting logical operations with register-controlled shifts (`tst r0, r1, lsl r2`: run-time shifter carry); NEON `vld1`/`vst1` (multiple structures, single lane, all lanes), bitwise operations, integer add/sub/mul/compare/min/max, float add/sub/mul/mla/mls/fma/abd/compare/min/max, `vcvt` between 32-bit integers and floats; VFP `vldr`/`vstr`/`vldm`/`vstm`/`vpush`/`vpop`, core <-> S/D moves, `vmov`/`vabs`/`vneg`, add/sub/mul/nmul/div/sqrt/mla/mls, `vmov #imm`, `vcvt` (int, f32 <-> f64), `vcmp`/`vcmpe` (flags into FPSCR), `vmrs APSR_nzcv`. Floating point runs on the host FPU: the host FPCR is switched only inside a *run* (NEON: standard FPSCR; VFP: the guest's FZ/DN/RMode), closed before any out-of-line operation, branch or region end, so the runtime's C code never sees a modified FPCR. `A32LIFT_INLINE=<mask>` switches groups off for bisecting.
- **Code discovery** (everything below fixed a real "no lifted code" stop on MK8D): PIC switch tables (`adr; ldr; add pc`, also with the table directly after the branch), conditional pc-relative function pointers (`ldr rX,[pc,#n]; cmp; addeq rY,pc,rX`), jumps into the middle of unrolled division sequences, `mov lr, pc; b`, and a sweep over every stretch of text no walk visited (literal-pool garbage is lifted and never executed; +4.6 % instructions).
- **Core fixes found by the new fuzz** (`a32_neon.c`, `a32_vfp.c`, `a32_decode_arm.c`): `vld4` all-lanes with size 0b11 used 8-byte elements; `vqrshl`/`vqshl` 64-bit saturation overflowed the 128-bit intermediate; `vrecps`/`vrsqrts` were fused (AArch32 is not); `vcvt.f16.f32` ignored the standard FPSCR; `vmaxnm`/`vminnm` mishandled signalling NaNs and flushed inputs; `pli` and the `0xf4`-space words with bit 20 set were decoded as NEON loads (wrote back a base register).
- Tests: `runtime/tests/a32/fuzz_all.py` (driver around `fuzz.py`: survives Unicorn's SIGILL on some NEON encodings, rerunning the chunk without the word), `fuzz.py` mnemonics via clang + llvm-objdump (no llvm-mc needed), `runtime/tests/a32jit/progtest.{py,c}` + `progs/` (C programs compiled for armv7a ARM and Thumb-2 with the system clang, run lifted and interpreted, compared with the same source compiled for the host), `difftest` randomises FZ/DN/RMode, `make -C runtime test-a32`.

## Verification (Apple M5, macOS, 2026-10-26)
- **MK8D base 1.0 boots headless**, `NAPPLE_A32_JITSTATS=1`: exit 0, **0 exits to the dispatcher (unlifted pc)**, 0 interpreted instructions, over 40 runs of 25 s (see the log lines below) and scripted 60 s runs reaching the menus and the attract race. fps in a 60 s window with `NAPPLE_PERF_LOG=1` and the input script: 50.7-52.0 (47.2 once while shaders compiled), 2808 frames in 60 s; before (previous lifted + interpreter mixed mode, same machine class) 44-45 fps and 3707-3799 frames in 90 s. The ceiling is gfx (guest blocked in SyncWait), not the CPU any more.
- LAS, SMO and ACNH boot headless 45 s: exit 0, no CRASH (2623 / 2082 / 1202 frames).
- Wild-pc crash: not reproduced in 72 headless runs of 20-25 s (32 + 40) of the lifted image. The two "no lifted code at this pc" stops seen while developing were not that crash but missing entry points (a conditional pc-relative function pointer at 0x94d12c and a PIC switch table at 0x3cff1c preceded by 12 `vmov`s), both fixed in the discovery; an interpreter-era report of a wild pc remains unexplained by itself, but a stray pc can no longer run anything: it stops the thread with the pc and the call chain.

## Documented deviations of Unicorn (QEMU 5.0) from the ARM ARM (filtered in `fuzz.py`, reason next to each filter)
`vabd.s32` / `vaba.s32` take the absolute value of the wrapped difference (this core and the lifted code use the exact difference); `vmaxnm.f64` / `vminnm.f64` with NaN operands; Advanced SIMD sets cumulative FPSCR exception bits (not compared for NEON); unpredictable encodings (pc as a destination of multiplies, `ldrd` with Rm = Rt/Rt2, `vmov Sn, pc`). The lifted code takes its cumulative exception flags from the host FPU; the interpreter derives them in software and differs on flushed results and square roots, so `difftest` does not compare those six bits (it compares everything else of FPSCR).

## Not done / limits
- VFP and NEON are partly inline (the table above); the remaining ones cost a spill/reload and a call each. Inline `vtbl`/`vext`/`vzip`, shifts and `vld2`-`vld4` are the next candidates (`7e00xx` in main is a `vtbl`-heavy loop executing 390k times per 45 s).
- Computed jumps into places no recogniser knows still stop the thread; collect them with the `A32_INTERP=1` debug runtime and `NAPPLE_A32_JITLOG=<file>`, feed back as `a32jit.seeds`. 0 were found in 150 s scripted runs after the sweep.
- iOS packaging of `a32jit.dylib` is described in docs/architecture/aarch32.md and not done.
- C sources were not run through clang-format (not installed on this Mac); they follow the file's style.
- `make -C gfx test` and `swift test` were not run (nothing in gfx or studio changed).
