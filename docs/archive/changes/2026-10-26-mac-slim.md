# 2026-10-26 mac-slim: warnings, size, build time, cache cap, `napple clean`

Branch `claude/mac-slim-2026-10-26-slim`. Mac only; no behaviour change except the new cache cap and the new subcommand.

## What changed
- **Warnings.** gfx: removed three dead variables (`idx` in `mtl_shader.m`, `g_pk` and `g_state_epoch_stage` in `mtl_replay.m`). Studio: removed the `.v5` language-mode override from `Package.swift` (the package now builds in Swift 6 mode), marked `pick(...)` `@MainActor`, dropped a useless `try` in `NappleCLI.swift`. Result: 0 warnings in every Obj-C file (`-Wall -Wextra`, runtime without `-Wno-unused-parameter` too) and 0 Swift warnings. No suppression was added. The runtime still prints two C warnings in files owned by code-slim (`services/ncm.c` `want_id`, `a32/a32_neon.c` `recip_estimate_int`). `frontend.m` still calls the CVDisplayLink API that macOS 15 deprecates (the Makefile keeps `-Wno-deprecated-declarations`); moving to `NSView.displayLink` is a behaviour change and was left out.
- **Size.** Release profile: `lto = "fat"` (was thin), `strip = "none"` (rustup's `rust-objcopy` aborts on this toolchain and printed a warning on every build; stripping is done by `strip -x` in `studio/build_app.sh`). Runtime link: `-Wl,-dead_strip -Wl,-x`; duplicate `-framework` flags removed. `studio/build_app.sh` strips the four binaries it bundles. No dSYM is produced anywhere. `-Os` was measured and rejected: -2.5 % binary size for a risk on the frame rate. `panic = "abort"` was already set.
- **Build time.** All five Makefiles (audio, input, frontend, gfx, runtime) now use `-MMD -MP` dependency files (touching `kernel.c` rebuilds 1 object; touching `napple.h` rebuilds the 59 objects that include it, not all) and build in parallel by default (`MAKEFLAGS += -j<ncpu>`). `runtime/Makefile` `OPT` is overridable (`make OPT=-Os`). `cargo tree -d` shows duplicates only in dev/build dependencies (bindgen/unicorn), none in the shipped CLI, so there was nothing to dedupe.
- **Cache cap.** `gfx/src/cache_trim.{c,h}`: at gfx init the cache directory (`<save-root>/<title id>/cache`) is trimmed oldest-file-first to `NAPPLE_GFX_CACHE_MAX_MB` (default 1024, 0 = unlimited). The prewarm manifests `pipelines.bin` and `pipelines-seed.bin` are never removed. Test: `gfx/tests/t_cache_trim.c`. A cold 45 s boot writes 0 to 25 MB (below), so the default is far above normal use; a trim logs `shader cache: N MB over the M MB cap, removed ...`.
- **`napple clean`.** `crates/napple-cli/src/clean.rs` (+ registration and a usage line in `main.rs`). `napple clean [--shader-cache] [--build-cache DIR] [--engine DIR] [--save-root DIR] [--dry-run]` lists and removes: per-title shader caches, `DIR/.napple-cache.nosync` and the `napple-runtime`, `napple-runtime-ios`, `napple-launcher` copies inside a built game folder. Prints sizes; `--dry-run` removes nothing. Saves, keys, firmware and game files are never touched. 3 unit tests.
- **Format and lint.** `.clang-format` (minimal-diff style: 4 spaces, attached braces, 160 columns) and a single formatting commit over every tracked `.m` (22 files, third_party excluded). `studio/.swiftformat` and `studio/.swiftlint.yml` (neither tool is installed on this Mac, so they were not run).
- **Prune.** Untracked the committed `studio/packaging/__pycache__/*.pyc` and ignored `__pycache__/` in `studio/.gitignore`. A scan for Obj-C functions with a single reference found none (the compiler already reports unused statics). Packaging files (`install.sh`, `dmg_settings.py`, `gen_assets.py`, `entitlements.plist`, DMG backgrounds) are all referenced by `make_release.sh`, `release.yml`, the site or the docs and were kept.

All 12 boots: exit 0, no CRASH. Frame counts are within the 2 % budget for all four titles. Notes on the numbers: peak RSS is not comparable on LAS (359 to 944 MB between runs of the same binary; the other three: SMO 921/919, ACNH 1205/1515, MK8D 1606/1638 MB before/after, ACNH differing by 300 MB in one sample); "time to first frame" is approximated by the time the guest logs NotifyRunning because the runtime has no first-present log line (adding one would be a runtime change); the Studio.app, DMG and ZIP sizes and the full `tools/ci_build.sh` timing were not measured (it re-runs the whole pipeline and signs); the runtime/CLI clean times are wall-clock single samples.

## Verified
