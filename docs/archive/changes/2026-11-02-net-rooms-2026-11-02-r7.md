# net-rooms (2026-11-02-r7): LDN and LAN play between Napple instances over the internet

Branch `net-rooms-2026-11-02-r7`, Mac session, based on net-host-provider (r6), which is merged in. hand-off notes:
the hand-off notes. Guide: [online rooms](../../guides/online-rooms.md).

## What changed
- `crates/napple-room/` (new, std only, workspace member): the room server and its protocol (`proto.rs`, version 1). Rooms with an optional password,
  a member list, virtual addresses from a configurable subnet (default 10.13.0.0/16), keepalive, per-member byte and packet rate limits (token
  buckets), limits on members per room, rooms and connections, a bounded send queue per member, unicast and broadcast relay of PACKET frames with
  anti-spoofing, LDN advertise / scan. `napple-room list HOST` lists rooms. `cargo test -p napple-room`: 13 tests.
- `runtime/src/net/net_room.c`, `net_room_vlan.c`, `net_room_ldn.c`, `net_room.h` (new): the runtime client inside the host provider, active only with
  `NAPPLE_ROOM`.
  - Connection: worker thread, a non-blocking outgoing queue, reconnects asking for the same address.
  - Virtual LAN: nifm reports the virtual interface. Guest UDP and TCP to virtual addresses and broadcasts go through the room; guest sockets stay
    real host sockets on ephemeral ports (loopback injection with a source header for UDP, loopback splices for TCP).
  - LDN: networks advertised to and scanned from the server, session frames as room packets, node addresses are virtual addresses.
- Hooks (additive): `net_host_sock.c` (bind / listen / accept / connect / send / recv / names / close), `net_host_ldn.c` (every entry point goes to
  `net_room_ldn.c` while a room is configured; the NetworkInfo / node encoders are exported), `net_host.c` (nifm through the room when configured;
  the room starts with the provider).
- `runtime/tests/test_net_room.c` + Makefile rules (`make -C runtime test-net-room`, part of `test-services`; builds the server with cargo).
- Docs: `docs/guides/online-rooms.md`, guides index row, `NAPPLE_ROOM`, `NAPPLE_ROOM_PASSWORD`, `NAPPLE_ROOM_NICK`, `NAPPLE_VLAN`,
  `NAPPLE_ROOM_SERVER_BIN` in `docs/reference/environment-variables.md`.

## Status
- Tested: `cargo test -p napple-room` (13 tests); `make -C runtime test test-services test-ipc-reference` green (`test_net_room`: a real server plus two
  consoles as two processes, 39 + 22 checks, 5 repeated runs clean).
- Verified on MK8D (update v1376256), two headless instances in one room on one Mac, LAN Play: both bind UDP 49152 / 40000 / 30000 on their own
  virtual address. Each receives the other's 873-byte LAN session announcement on port 30000 from the other's 10.13.0.x address, through the server.
  Not reached: a lobby where each sees the other. About 2 s after starting the session search, MK8D shows error 2618-0006 and aborts. It does the same
  with one instance on the real LAN without rooms, and in Wireless Play (LDN, through the room and through r6's LAN transport). So it is a runtime gap
  outside rooms, not yet diagnosed (see the hand-off notes).
- Needed for LAN Play to get that far: nifm `IGeneralService::GetCurrentIpConfigInfo` (still a stub in `offline.c`, not owned here). The patch used is in
  the hand-off notes.
- Four titles (SMO, LAS, MK8D, ACNH) boot 45 s with and without `NAPPLE_NET=host`: rc 0, no unsupported svc.
