# 2026-10-26 f64-isa: bit-exact double precision for the Maxwell translator, and the rare-ISA audit

Branch `claude/f64-isa-2026-10-26-macos1` (Linux cloud session; Metal checks are written but not run). Owner area: `gfx/src/shader/`.

## What changed
- **Double precision is translated.** DADD, DMUL, DFMA, DSETP, DMNMX, DSET and the 64-bit forms of F2F, F2I and I2F no longer fail with "double precision is not supported (Metal has no f64)". A binary64 is a register pair
  (even register = low word) carried as a `ulong` of raw bits; every operation is a call into a small integer library that is emitted once per shader that needs it.
- **One source, two languages.** `src/shader/soft_double_core.inc` holds the algorithms in the subset shared by C and Metal (`uint` 32-bit, `ulong` 64-bit, no pointers).
  `soft_double.h` compiles it as C (the host reference); `soft_double_msl.h` stringifies the same tokens (`#__VA_ARGS__` after macro expansion) into `sd_msl_source`, which the translator appends to the shader.
  The MSL is therefore not a re-implementation: the test vectors that pass for the C build validate the text that reaches the Metal compiler.
- **Semantics**: IEEE 754 round to nearest even and the three directed modes (the Maxwell rounding field: 0 RN, 1 RM, 2 RP, 3 RZ), full denormal support (no flush), single-rounding fused multiply-add,
  exact zero signs (a cancelling sum is +0, -0 under RM), every NaN result is the canonical `0x7FFFFFFFFFFFFFFF` (the hardware does not propagate payloads), F2I saturates and maps NaN to 0, DMNMX lets the non-NaN operand win and orders -0 below +0.
- Operand forms: register pair, two constant-buffer words, the 20-bit immediate that fills the top of the high word; the neg/abs modifier bits of every form; DFMA's cbuf-in-C form (0x53); the DSETP/DSET compare codes and combine operators.
- `NAPPLE_F64=off` restores the old refusal (emulation level switch for A/B debugging a suspect shader). `ShaderKey` is untouched.
- **Rare-ISA audit** (40 items, table below): video ALU ops, IMAD32I, FCHK, PIXLD, LEPC, CAL/RET/JMP/JCAL/JMX, CCTL/CCTLL implemented or made structural; the rest refused by name.
- **Layout fixes from envytools** (MIT, the Maxwell disassembler tables; facts only): IMAD read bits 49/51 as negations and 53 as `.HI`; the hardware has `.X` at 49, `.SAT` at 50, `.HI` at 54, and no negations. IMAD now follows the tables
  (`.SAT`/`.X`/`.CC` fail cleanly). The FSET cbuf mask no longer swallows DSET (0x49).

### Performance note (stretch)
Static cost of one call, in LLVM IR instructions after -O2 (branches excluded): add 135, mul 146, fma 236, compare 20, min/max 23, rint 34, int->f64 31, f64->int 55, f64->f32 84, f32->f64 31, int64->f32 39.
Host timing on random normal operands (x86-64, -O2, mispredicted branches included): add 13 ns, mul 9 ns, fma 21 ns, compare 7 ns, f64->f32 3 ns. On the GPU each op is a few dozen to ~250 dependent 32/64-bit integer instructions
(64-bit adds and shifts are emulated by the Apple GPU as 32-bit pairs, so expect 2-4x the IR count in ALU cycles); a shader doing doubles is slow per double but doubles are rare in game shaders.
The whole library is emitted whole (about 11 KB of MSL) in every shader with a double op; the Metal compiler drops what is unused.

**refused** = fails with a named error because no application shader reaches it. "Test" is in `gfx/tests/t_xlate.m` (Linux-runnable text assertions; the emitted MSL compile is the Mac check).

## Not done / limits
- The Maxwell F2F float-narrowing rounding is read from bits 39-40 when bit 42 is clear; envytools lists only 0 ("round") and 3 ("pass") for that field, so a directed-rounding F2F.F32.F64 may use another encoding. Default rounding is right.
- F2F f64>f16 goes through f32 (two roundings).
- VMAD `.PO`, VADD bits 56-57 and the `.CC` bits of the video family are not decoded (nothing in either corpus uses the family).
- FTZ bits of F2F/F2I on a double are ignored (doubles have no flush).
- Nothing here was run on a Mac: the translator output has not been through `newLibraryWithSource`, and no corpus shader contains a double (so no real word confirms the D-op layouts; they match envytools).
