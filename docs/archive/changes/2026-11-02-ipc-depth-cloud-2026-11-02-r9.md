# ipc-depth-cloud (2026-11-02, batch r9): 98 IPC rows made real (87 new, 11 stub to impl)

Branch `ipc-depth-cloud-2026-11-02-r9` (cloud session on Linux, base `main` = `57431a7`).

Status: **tested** (unit tests ran on Linux against `tools/linux-check`), **unbuilt** (no line was compiled on macOS). Nothing was run on a Mac or with a
game.

Goal: raise IPC command depth (`IPC_IMPL` against `IPC_STUB`). Across `runtime/src`, rows went from 1473 impl / 257 stub to 1571 impl / 246 stub.
The `test_ipc_reference` check still reports `missing 0` over 1325 application-reachable ids.

## Scope decisions
- **Few stub rows were in scope.** Only about 50 of the 257 `IPC_STUB` rows were in files this session could edit and were not network rows: vi, btm,
  lm, ovln, aoc, mii_img, push/notif, olsc, bcat, prepo and sfdnsres. Other sessions own fs, account, applet, ldn and the nifm / bsd / ssl / nsd /
  friend part of offline.c.
- **Stub rows converted (11).** Each now has documented behaviour and a test.
- **Stub rows left alone.** Rows whose arguments are not documented stayed documented defaults. These are btm 1/2 (filter values unknown), mii_img
  18-20, lm 11, ovln 1 (no receiver exists), npns 101-154, sfdnsres 14/15/100-104, prepo 50100/90100, olsc and the bcat scheduling rows.
- **New rows (87).** The rest of the depth comes from ids that the switchbrew reference fixtures list and that had no row: set:sys, time, vi
  display, pctl, pdm, lbl and ncm. They were added as real rows backed by state, so a Set is read back by its Get. Most are marked `n` (not
  application-reachable) in the fixtures.
- **Nothing persists across runs.** set:sys, notif:a and pctl keep their stores for the life of the process only.
- **Napple's own result values and defaults.** Where the console's result values or defaults are not documented, napple's choice is used and
  marked `[unverified]` in the source.

## Tests
On Linux, through `tools/linux-check` (gcc and clang, plus gcc with `-fsanitize=address,undefined`), these tests were extended: test_svc_settings,
test_svc_time, test_svc_vi, test_svc_aoc, test_svc_pctl, test_svc_push, test_svc_bcat, test_svc_pdm, test_svc_lbl and test_svc_ncm. The hand-off notes
lists the commands and check counts.

Two fixes inside `runtime/tests/`:
- `test_svc_vi.c`: a one-word reply buffer overflowed (found by ASan; test-only).
- `test_svc_pctl.c`: an aoc expectation that this branch changed.

## Risks
- **Layouts from switchbrew / libnx, not checked on a console.** The riskiest are:
  - the notif:a AlarmSetting size;
  - the pctl PIN buffer kind;
  - the ISystemDisplayService 32xx argument order;
  - the PurchasedProductInfo "nothing to pop" result.
- **ncm ContentInfo layout.** `ncm_core.c` reads the content type at ContentInfo byte 0x17. The libnx `NcmContentInfo` puts `content_type` at 0x16 and
  `id_offset` at 0x17. Recorded as a finding, not changed here.
